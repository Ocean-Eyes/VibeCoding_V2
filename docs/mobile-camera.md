# 모바일 카메라 점검

카메라를 여는 코드는 `app.js`, `belt-lesson.js`, `baemilgi-lesson.js`의 세 경로다. 아래 여섯 화면/모드를 검사한다. 메치기 세 기술은 시연만 제공하며 카메라 연결 기능은 없다.

| 화면 | 경로 | 확인한 연결 기능 |
| --- | --- | --- |
| 가상 띠 | `/basics/belt` | 전면 카메라, 가이드, 종료/메뉴 복귀 시 해제 |
| 실제 띠 | `/basics/belt`의 실제 띠 모드 | 카메라 영상, 색 표시 추적 경로, 종료 시 해제 |
| 십자조르기 | `/katame-waza/shime-waza/nami-juji-jime` | 카메라, 자세·양손 추적, 추적 재연결 |
| 역십자 조르기 | `/katame-waza/shime-waza/gyaku-juji-jime` | 카메라, 자세·양손 추적, 추적 재연결 |
| 외십자 조르기 | `/katame-waza/shime-waza/kata-juji-jime` | 카메라, 자세·양손 추적, 추적 재연결 |
| 배밀기 도전 | `/basics/hindu-push-up` | 후면 광각 우선, 자세 추적, 추적 재연결 |

## 공통 처리

- `camera-playback.js`: 영상을 표시하고 무음·인라인 속성을 설정한 뒤 재생한다. 자동 재생 차단 시 연결을 유지하고 사용자의 탭으로 다시 재생한다. 연결 취소와 메뉴 이동은 대기 중인 재생도 해제한다.
- `vision-tracking.js`: Worker를 먼저 사용하고, Worker 그래픽 기능이 없거나 초기화에 실패하면 같은 모델을 DOM Canvas에서 실행한다. 기종 이름으로 기능을 제한하지 않는다.
- 조르기의 기존 자세·손 모델과 배밀기의 기존 자세 모델, 버전, 임곗값을 유지한다. 추적 실패 시 영상은 남기고 재연결을 제공하며, 모든 종료 경로에서 스트림과 추적기를 정리한다.

## 자동 검증

빌드 후 로컬 서버를 실행하고 Playwright 패키지 경로를 전달한다. 서버 주소는 `SITE_URL`로 지정하며 기본값은 `http://127.0.0.1:5186/dist/`다.

```sh
node scripts/browser-mobile-cameras.cjs <playwright-package-path>
node scripts/browser-baemilgi-camera.cjs <playwright-package-path>
node scripts/browser-baemilgi-model.cjs <playwright-package-path>
```

- 모바일 화면/터치 조건 두 가지(440×956, 412×915)에서 여섯 화면의 정상 연결, 영상 재생 차단/재개, 권한 거부, 메뉴 이동 뒤 늦게 도착한 권한 허용을 검사한다. 추적 화면 네 곳은 Worker 초기화 실패 시 대체 실행도 검사한다. 합계 56개 시나리오다.
- 배밀기의 렌즈 선택, 재생 대기 중 취소, 모델 초기화 중 취소 등 12개 추가 시나리오를 검사한다.
- 실제 MediaPipe 모델을 다운로드해 배밀기와 조르기 각각 Worker/Canvas 경로에서 초기화 및 프레임 분석을 검사한다. 테스트 카메라에 사람이 없을 때 횟수나 손 인식을 만들어 내지 않는지도 확인한다.

모바일 시나리오는 Chromium의 화면/터치 모의 환경과 테스트 스트림을 사용한다. 실제 iPhone Chrome/Safari 또는 Android 기기의 카메라 권한·렌즈·재생 정책을 직접 확인한 결과로 해석하지 않는다. 배포 후 실기기 확인은 별도로 필요하다.

## 2026-11-08 검증 결과

- 전체 Node 테스트 2,145개, 모바일 카메라 시나리오 56개, 배밀기 카메라 시나리오 12개 통과.
- 실제 모델의 배밀기/조르기 × Worker/Canvas 초기화 및 프레임 분석 네 경로 통과. 외부 모델 다운로드를 허용한 실행 환경에서 확인했다.
- 기존 띠 시연·카메라·가이드·종료 검사, 배밀기 집계·기록·실제 모델 검사, 손 표시·복구·거울·종료 검사 통과.
- 기존 브라우저 검사 두 곳의 입력도 현재 제품에 맞췄다. 기초 카드 수는 배밀기를 포함한 3개이며, 지속적인 손 위치 이동 샘플은 대응하는 자세 손목도 같은 위치로 이동시킨다. 손만 이동하고 손목이 남는 기존 샘플의 시간 초과는 수정 전 `app.js`에서도 재현했다. 한 프레임의 잘못된 손 검출은 계속 별도로 검사한다.
