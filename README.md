# Terrain Point Cloud Studio

지구상의 **원하는 위치를 3D 포인트 클라우드로** 만들어 브라우저에서 돌려보고, `PLY` / `CSV` / `PNG`로 내보내는 정적 웹 앱입니다. 빌드 도구·서버·API 키가 전혀 필요 없습니다. `index.html` 하나가 전부입니다.

👉 **https://ocean-eyes.github.io/VibeCoding_V2/**

## 구글 어스 DEM을 쓰지 않은 이유

처음 아이디어는 "구글 어스의 DEM을 쓰자"였지만, 실제로는 불가능합니다.

| | 상황 |
|---|---|
| **Google Earth / Maps 지형 타일** | 비공개 내부 엔드포인트. 직접 호출·스크래핑은 서비스 약관 위반 |
| **Google Elevation API** | 포인트 쿼리 방식(요청당 최대 512점), 유료, 결과 캐싱·파생물 저장 제한. 수십만 점 규모엔 부적합 |

그래서 **구글 어스가 내부적으로 쓰는 것과 사실상 같은 원천 데이터**를 공개 채널로 받아옵니다.

| 역할 | 소스 | 비고 |
|---|---|---|
| 고도(DEM) | [AWS Terrain Tiles](https://registry.opendata.aws/terrain-tiles/) — SRTM · ASTER GDEM · USGS 3DEP/NED · GEBCO · CDEM 합성 | Terrarium PNG 인코딩, API 키 불필요, CORS 허용, 최대 z14 |
| 색상 | Esri World Imagery | 위성영상 타일, 키 불필요, CORS 허용 |
| 위치 검색 | OSM Nominatim | 검색 버튼당 1회 호출 |

## LiDAR 스캔 시뮬레이션

**스캔 방식**을 `LiDAR 스캔`으로 바꾸면, 지형 표면에 센서를 세우고 **실제 제조사 빔 패턴 그대로** 레이캐스팅합니다. 빔이 지형을 맞히면 점이 생기고, 하늘로 빠져나가면 실제 센서처럼 **무반환(no return)** 으로 버려집니다.

- 센서 원점은 화면 중심(= 입력한 위경도)의 지표면 + **설치 높이**
- 방위각은 1회전을 모델의 수평 해상도만큼 등분
- 각 반환점은 **거리 · 채널(ring) 번호 · 방위각 · 모의 반사강도**를 함께 가집니다
- 점 크기는 `거리 × 각도 간격`으로 계산한 **빔 풋프린트**라, 멀수록 성기고 커지는 실제 밀도 분포가 그대로 보입니다

### 채널별 선택 가능 모델

| 채널 | 모델 | 수직 FOV | 수직 간격 | 거리(10%) | 빔 패턴 출처 |
|---|---|---|---|---|---|
| **16** | Velodyne VLP-16 (Puck) | 30° (+15/−15) | 균일 2.00° | 100 m | 데이터시트 (정확히 균일) |
| **16** | Velodyne VLP-16 Hi-Res | 20° (+10/−10) | 균일 1.33° | 100 m | 데이터시트 (정확히 균일) |
| **16** | Ouster OS1-16 *(1세대·단종)* | 33.2° | 균일 2.21° | ~60 m | 1세대 공칭 사양 |
| **32** | Velodyne HDL-32E | 41.3° (+10.67/−30.67) | 균일 1.33° | 100 m | 데이터시트 (하방 편향) |
| **32** | Velodyne VLP-32C (Ultra Puck) | 40° (+15/−25) | **비균일** 0.33°~9.36° | 200 m | **제조사 각도표** |
| **32** | Ouster OS0/OS1/OS2-32 | 90° / 45° / 22.5° | 균일 | 35 / 90 / 200 m | 데이터시트 + Uniform 배치 |
| **64** | Velodyne HDL-64E S3 | 26.5° (+1.96/−24.56) | **비균일** 0.21°~0.65° | 120 m | **실제 개체 캘리브레이션** |
| **64** | Ouster OS0/OS1/OS2-64 | 90° / 45° / 22.5° | 균일 | 35 / 90 / 200 m | 데이터시트 + Uniform 배치 |
| **128** | Velodyne VLS-128 (Alpha Prime) | 40° (+15/−25) | **비균일** 0.11°~5.42° | 245 m | **제조사 각도표** |
| **128** | Ouster OS0/OS1/OS2-128 | 90° / 45° / 22.5° | 균일 | 35 / 90 / 200 m | 데이터시트 + Uniform 배치 |

**Velodyne의 비균일 각도표는 추정값이 아닙니다.** 공식 ROS 드라이버([ros-drivers/velodyne](https://github.com/ros-drivers/velodyne))의 `velodyne_pointcloud/params` 캘리브레이션 파일에서 각 레이저의 `vert_correction` 값을 그대로 읽어 넣었습니다. VLS-128의 최소 간격 0.110°, VLP-32C의 0.333°은 각 데이터시트의 공표값과 일치합니다. 균일 모델(VLP-16/Hi-Res/HDL-32E)은 정의상 정확히 균일해서 양 끝 각도와 간격으로 생성합니다.

**Ouster**는 모든 개체가 자기만의 `beam_altitude_angles` 테이블을 가지고 출하되므로, 여기서는 기본 **Uniform** 배치(수직 FOV를 채널 수로 등분)를 씁니다. 수직 FOV(OS0 90° / OS1 45° / OS2 22.5°)와 거리값은 제품 데이터시트 기준입니다. Gradient·Above/Below Horizon 배치는 지원하지 않습니다.

### 이 시뮬레이션이 하지 않는 것

정직하게 적자면, 이건 **빔 기하 시뮬레이터**이지 센서 시뮬레이터가 아닙니다.

- 지형 원본이 **DEM z14 ≈ 7~10 m/px** 입니다. 그 사이는 보간된 매끄러운 면이라, 100 m 스캔은 실제 지형의 **거시 형상만** 재현합니다. 나무·건물·바위 같은 객체 단위 반환은 존재하지 않습니다 (패널에 원본 해상도와 경고를 표시합니다).
- 반사강도는 **입사각과 거리로 계산한 모의값**이며 실측 intensity가 아닙니다. PLY 주석에도 그렇게 적힙니다.
- 빔 발산각, 다중 반환(dual/multi return), 대기 감쇠, 모션 왜곡, 노이즈 모델은 넣지 않았습니다.
- 수직 과장을 1× 이외로 두면 빔 각도가 보기와 달라집니다. LiDAR 모드로 전환하면 자동으로 1×로 맞춥니다.

## 기능

- **위치 지정** — 지명 검색(Nominatim) 또는 위·경도 직접 입력, 프리셋 8곳(한라산·설악산·후지산·마터호른·그랜드캐니언·에베레스트 등)
- **영역 1–60 km**, **격자 128²–1024²** (최대 약 105만 점)
- **색상 모드 3종** — 위성영상 / 고도 컬러램프 / 경사도, 각 모드에 **음영기복(hillshade)** 합성 토글
- **수직 과장 0.5–6×**, 점 크기, 거리 페이드 실시간 조절 (타일 재다운로드 없음)
- **내보내기**
  - `PLY` (binary little-endian, XYZ + RGB) — CloudCompare · MeshLab · Blender에서 바로 열림
  - `CSV` (WGS84 위도, 경도, 고도 m, RGB) — QGIS · pandas용
  - `PNG` 스냅샷
  - LiDAR 모드에서는 PLY에 `ring`(uint16) · `intensity` · `range` 속성이 추가되고, CSV에는 거리 · 방위각 · 빔 고도각 · ring이 함께 들어갑니다
- **공유 링크** — `?lat=&lon=&km=&g=&ex=&c=&auto=1` (LiDAR 모드는 `&mode=lidar&model=&az=&sh=&rm=&lc=` 추가) 형태로 현재 장면을 URL에 담아 복사
- **온디맨드 렌더링** — 화면이 바뀔 때만 그리므로 100만 점을 띄워도 가만히 두면 GPU를 쓰지 않습니다

### 좌표계

| 출력 | 축 정의 |
|---|---|
| 화면 / PLY | `x` = 동쪽(m), `y` = 고도(m), `z` = 남쪽(m). 원점은 장면 중심 |
| CSV | WGS84 위도·경도 + 고도(m) |

> 내보내기 파일의 고도는 **수직 과장이 적용되지 않은 실제 미터**입니다. 과장은 화면 표시에만 적용됩니다.

## 동작 방식

```
위·경도 + 영역 크기
      ↓ 중심 기준 정사각형 bbox 계산
      ↓ 격자 밀도에 맞는 Web Mercator 줌 자동 선택 (타일 수 상한으로 클램프)
Terrarium DEM 타일 블록  ──┐
Esri 위성영상 타일 블록   ──┤ 하나의 캔버스로 모자이크
      ↓                   │
      ↓ 격자점마다 bilinear 샘플링 ←┘
      ↓ elev = (R × 256 + G + B ÷ 256) − 32768
      ↓ 중심차분으로 법선 → hillshade
THREE.Points (커스텀 셰이더, 원형 포인트 + 깊이 페이드)
      ↓ (LiDAR 모드)
      ↓ 센서 원점에서 채널 × 방위각 만큼 광선을 쏨
      ↓ 적응적 스텝으로 전진 → 지표면 교차 시 14회 이분탐색으로 정밀화
      ↓ 하늘로 빠지거나 영역을 벗어나면 무반환
반환점 = 위치 + 거리 + ring + 방위각 + 모의 반사강도
```

타일은 최대 6개씩 병렬로 받고 실패 시 2회 재시도합니다. 끝내 못 받은 타일은 DEM이면 0 m, 영상이면 회색으로 채우고 몇 장이 누락됐는지 알려줍니다.

## 로컬 실행

`file://`로 열면 ES 모듈과 CORS가 막히므로 간단한 정적 서버가 필요합니다.

```bash
python -m http.server 8080
# → http://localhost:8080
```

의존성은 CDN의 [three.js](https://threejs.org/) r170 하나뿐입니다.

## 라이선스와 데이터 이용 조건

코드는 MIT. **데이터는 각 제공처 조건을 따릅니다.**

- **고도** — AWS Terrain Tiles는 공개 데이터이며 출처 표기가 필요합니다: *SRTM (NASA/USGS), ASTER GDEM (NASA/METI), USGS 3DEP, GEBCO, Natural Resources Canada*. 표기는 앱 하단과 PLY 헤더 주석에 포함돼 있습니다.
- **위성영상** — Esri World Imagery는 출처 표기(*Esri, Maxar, Earthstar Geographics, and the GIS User Community*) 조건으로 표시가 허용됩니다. 다만 **영상 픽셀을 파일로 추출·재배포하는 것은 Esri 약관상 명확히 허용된 범위가 아닙니다.** 결과물을 배포하거나 상업적으로 쓸 계획이라면 색상 모드를 **고도 컬러램프** 또는 **경사도**로 두세요. 이 경우 내보낸 파일에는 Esri 유래 데이터가 전혀 포함되지 않고, PLY 헤더에도 그렇게 기록됩니다.
- **검색** — Nominatim [이용 정책](https://operations.osmfoundation.org/policies/nominatim/)에 따라 대량·자동 호출은 금지됩니다. 이 앱은 사용자가 검색을 누를 때만 1회 호출합니다.

## 정확도에 대해

전 지구 공개 DEM의 수직 오차는 대체로 ±10–16 m(SRTM 90% 신뢰수준) 수준이고, 수관(나무)·건물 높이가 지표면 고도에 섞여 있습니다. 미국 본토처럼 3DEP/NED가 들어간 지역은 훨씬 정밀합니다. **측량·설계 용도가 아니라 시각화·연구·프로토타이핑용**입니다.
