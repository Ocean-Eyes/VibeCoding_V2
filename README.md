# Just Judo

배포 대상: Vercel (GitHub 저장소 연동).

설치 없이 PC/노트북 웹브라우저에서 이용하는 유도 학습 도장입니다. Yuji Boku 붓글씨 서체의 柔道·基本·固技·投技, 종이 질감, 먹선, 붉은 낙관을 사용한 두루마리 도장 UI입니다. 상품 카드 대신 과정 칸과 기술 목록을 사용합니다. 특정 단체의 공식 서비스는 아닙니다.

## 메뉴와 현재 범위

첫 화면은 **기초 → 굳히기본 → 메치기본** 순서입니다.

- 기초: 도복 입는 법, 띠 매는 법, 낙법. 예정 레슨으로 표시하며 아직 실행되지 않습니다.
- 굳히기본 / 조르기: **십자조르기, 역십자 조르기, 외십자 조르기**를 각각 선택할 수 있습니다.
- 메치기본: 다음 레슨을 위한 메뉴이며 아직 실행되지 않습니다.

조르기 기술마다 그립 개념 설명, 손바닥 방향 개념도, IJF 공식 설명·시범 링크, 연습 화면 옆 기술 설명, 웹캠 손 위치 예비 연습이 있습니다. 이전의 일반 팔 벌리기·V자·파워 포즈 동작은 제거했습니다.

## 미션과 기록

1. 수련하기를 누르면 고정된 도복 상대 위에서 반투명 흰색 손이 준비 → 왼손 교차 → 오른손 교차 → 유지 → 풀기를 12초 주기로 시연합니다. 카메라는 아직 켜지지 않습니다.
2. 내 동작 연습을 눌러 카메라를 연결하세요. 처음에는 카메라 권한을 허용합니다. 연결되면 3초 준비 후 연습이 시작됩니다. 기술 설명과 그립 방향은 오른쪽 패널에서 봅니다.
3. 카메라에서 그립 준비 → 첫 손 교차 → 양손 교차 순서로 팔 위치를 따라합니다.
4. 각 단계는 팔 위치 50% 이상을 연속 3초 유지하면 통과합니다. 마지막 단계에서는 두 손목의 교차와 각 깃 목표까지의 거리도 확인합니다. TAP 안내를 1.5초 표시한 뒤 20 XP와 해당 기술의 예비 연습 완료 도장을 받습니다.
5. 기술별 XP는 최초 1회 지급하며 다시 연습해도 중복되지 않습니다. 현재 연습 보상은 3종 합계 60 XP이며, 이전 퀴즈에서 받은 XP는 유지합니다.

진행도는 브라우저 localStorage의 `just-judo-progress-v1`에 저장합니다. 저장이 차단되면 현재 방문 동안만 동작하며 이를 화면에 표시합니다. 강도관 공식 영상 버튼은 선택한 기술의 YouTube 영상을 엽니다. 영상 창을 열면 연습은 정지되며, 닫으면 플레이어가 해제됩니다. 메뉴로 나갈 때 카메라와 추론 Worker를 종료합니다.

## 웹캠 판정의 범위

**웹캠은 혼자 하는 교차 팔 위치의 예비 연습을 평가합니다. 실제 유도 기술의 숙련도·효과를 판정하지 않습니다.**

세 기술의 핵심 차이는 손바닥 방향입니다. 이것은 옆의 그립 설명으로 학습하며 웹캠이 자동 판정한다고 표시하지 않습니다. 세 기술에서 공유하는 팔 위치 예비 연습은 같습니다. 깃 잡기, 압박, 상대의 자세, 실제 조르기 완성도는 판정 범위 밖입니다. 상대와의 실습은 지도자의 지도를 받으세요.

- MediaPipe Pose Landmarker와 Hand Landmarker를 별도 Worker에서 실행합니다.
- 채점은 양어깨 중점·너비·기울기를 기준으로 정규화하며 골반이 화면 밖이어도 작동합니다. 상대 캐릭터의 위치·크기·기울기는 사용자 추적과 분리되어 고정됩니다.
- 목표의 상완·전완 길이는 인식된 사용자의 영상 속 팔 길이에 맞춥니다.
- 팔꿈치/손목 위치 오차를 어깨 너비로 정규화하여 `100 × exp(-3.5 × 평균오차)`로 점수를 계산합니다.
- 기술별 손바닥/손등 그립 그림을 화면 목표, 단계 미리보기, 오른쪽 설명에 표시합니다. 그림은 위에서 본 손 방향 개념도이며 실제 손바닥 방향의 자동 인식 결과가 아닙니다.
- 도복 상대는 별도 캔버스에 고정해서 그립니다. 흰색 손만 시연하며 파란 표시만 사용자의 손 위치를 따라갑니다. 뼈대는 기본으로 숨기며 관절 표시 옵션으로 켤 수 있습니다.
- 화면 안에 0~100점 동작 일치도와 3초 유지 진행, 피드백을 표시합니다. 시연 중이나 인식 누락 시에는 점수 대신 대시를 표시합니다. 손 그림에는 손바닥 주름과 손등의 손톱·관절을 구분하고, 별도의 흰 깃 막대는 표시하지 않습니다.
- 손가락은 관절 표시를 켰을 때 보조 시각화하고, 손 추적 수를 표시합니다. 손 모양 점수를 기술 정확성 점수에 합산하지 않습니다.
- 주요 관절이 가려지거나 추론 결과가 오래되면 채점을 멈춥니다.
- 신체가 인식되기 전에도 고정된 상대와 안내 손을 표시합니다. 인식 전에는 점수를 부여하지 않습니다.
- 추적 오류가 나도 영상은 유지하고 오류 및 재연결 버튼을 표시합니다.

영상을 서버로 전송하거나 저장하지 않습니다. 최초 카메라 연결 시 jsDelivr의 고정 버전 `@mediapipe/tasks-vision@0.10.22-rc.20250304`와 Google Storage의 모델 파일을 다운로드합니다. 글꼴은 Google Fonts를 사용하며 실패하면 시스템 글꼴로 표시됩니다. 웹캠에는 HTTPS 또는 localhost가 필요합니다.

## 개발과 배포

Node.js 20 이상, 별도 앱 의존성 설치 없이 실행합니다.

```sh
npm start
# http://localhost:5173
npm test
```

Vercel에서 `Ocean-Eyes/VibeCoding_V2` 저장소를 Import하세요. Root Directory는 저장소 루트(`.`)이며, `vercel.json`이 Build Command `npm run build`, Output Directory `dist`, Framework Other를 설정합니다. 별도 환경 변수는 필요 없습니다. GitHub Pages 자동 배포는 중단했고 기존 워크플로는 수동 실행만 가능합니다.

빌드는 HTML·CSS·모든 로컬 JS 모듈 및 Worker URL에 동일한 콘텐츠 버전을 붙여 이전 캐시와 새 파일이 섞이는 것을 방지합니다. Vercel 응답은 캐시 재검증을 사용합니다.

Playwright 패키지가 있는 환경에서:

```sh
node scripts/browser-dojo.cjs <Playwright 패키지 경로>
node scripts/browser-regressions.cjs <Playwright 패키지 경로>
npm run build
node scripts/browser-entry.cjs <Playwright 패키지 경로>
node scripts/browser-demonstration.cjs <Playwright 패키지 경로>
```

`SITE_URL` 환경 변수로 배포 사이트를 검사할 수 있습니다. 도장 검사에는 메뉴·즉시 연습 진입·기술별 설명·저장·중복 XP 방지·강도관 영상 연결·기본 관절 숨김·가상 상대 탭·가상 카메라의 실제 모델 초기화·메뉴 복귀 시 카메라 해제·반응형 레이아웃이 포함됩니다. 미션 완료 흐름은 합성 관절을 주입하여 검증합니다. 회귀 검사는 공개 인물 사진을 영상 입력으로 사용하며 오류도 강제로 주입합니다. **이 검사는 실제 사용자가 유도 동작을 하는 웹캠 환경의 인식률 검증을 대신하지 않습니다.**

강도관 영상 링크는 [강도관 공식 기술 목록](https://kdkjd.org/names-of-judo-techniques/)에서 확인했습니다. 영상 임베드가 제한되면 플레이어 아래 YouTube 링크를 이용합니다. 가상 상대의 탭은 손 위치 유지로 발생하는 게임 이벤트이며 실제 압박의 시뮬레이션이 아닙니다.

진입 회귀 검사(`browser-entry.cjs`)는 빌드 산출물에서 구형 Canvas 환경, 이전 무버전 모듈 캐시, 연습 모듈 로드 실패, 로딩 중 메뉴 복귀를 확인합니다. 연습 모듈 초기화는 메뉴에서 분리되어 실패해도 기술 설명과 메뉴 복귀는 사용할 수 있습니다.

## 교차 그립 도식의 기준

[강도관 기술 정의](https://kdkjd.org/names-of-judo-techniques/)와 IJF의
[십자조르기](https://judo.ijf.org/techniques/Nami-juji-jime),
[역십자조르기](https://judo.ijf.org/techniques/gyaku-juji-jime)를 기준으로 구분합니다.
십자는 양 엄지가 안쪽·손바닥 아래·양손 밀기, 역십자는 양손의 네 손가락이 안쪽·손바닥 위·양팔 조이기입니다.
외십자는 왼손 네 손가락 안쪽·당기기와 오른손 엄지 안쪽·밀기의 조합입니다.
설명 그림과 시연은 동일한 V자 깃과 교차 손목 배치를 사용합니다. 손등을 보는 닫힌 그립에서는 접힌 손끝과 손톱을 그리지 않습니다.
시연의 팔 움직임은 작용 방향을 표현하는 2D 도식입니다. 점수는 팔 위치만 평가하며 손바닥 방향, 실제 깃 안팎, 압박은 판정하지 않습니다.

## 참고 자료 기반 손 모델

사용자가 제공한 `references/ms_arm_and_hand`의 AAH 모델에서 손목 이하 28개 body의 관절 위치·축·범위와 말단 골격 STL의 손끝 위치를 추출했습니다. `references/hands.md`의 MediaPipe 순서대로 21개 관절점을 구성합니다. 좌우 손은 해부학적 속성이며, 화면 좌우 위치나 카메라 반전으로 바꾸지 않습니다. 손바닥 전환은 깊이축까지 회전시킵니다.

`src/hand-rig-data.js`는 원본 XML의 SHA256을 기록합니다. `src/hand-rig.js`가 범위 내 관절 회전과 뼈 길이를 유지합니다. 피부·흰 장갑 표면은 이 골격을 감싸도록 별도로 만든 부드러운 표면이며, 원본 자료에 피부 메시가 포함되어 있다는 의미는 아닙니다. 압박·깃 마찰을 계산하는 생체역학 시뮬레이터도 아닙니다.

실행 시 GPU에 의존하지 않도록 관절 모델의 여덟 가지 좌우·앞뒤·재질 렌더를 `assets/hands-aah-v1/`에 저장합니다. 실패한 AI 생성 사진은 앱에 사용하지 않습니다. 원본 모델의 MIT 고지는 `assets/AAH-LICENSE.txt`에 포함했습니다. 큰 원본 참고 폴더는 배포물에 포함하지 않습니다.

재생성 (저장소 루트에서 로컬 서버 실행 후):

```sh
python scripts/extract-hand-rig.py
node scripts/render-hand-assets.cjs <Playwright 패키지 경로>
node scripts/browser-hand-rig.cjs <Playwright 패키지 경로>
```

## 실시간 흰 장갑

자동 시연에서는 AAH 참고 모델의 고정 그립을 사용합니다. 카메라 연습에서는 기존 MediaPipe HandLandmarker가 반환한 21개 관절을 매 프레임 흰 장갑 표면으로 그립니다. 손가락마다 굽힘을 반영하며, 두 손의 검출 순서가 바뀌어도 몸의 좌우 손목과 직전 위치를 이용해 동일한 손에 연결합니다. 상대 캐릭터는 고정됩니다.

`src/live-hands.js`의 적응형 필터와 프레임 사이 보간은 표시 좌표에만 적용합니다. 원래 인식 모델·신뢰도 설정과 팔 위치 채점 입력은 유지합니다. 인식이 끊긴 손은 숨기고 다시 검출되면 필터를 초기화합니다. 실제 손가락은 추적하더라도 깃을 실제로 잡았는지, 압박이 적절한지는 채점하지 않습니다.

`src/live-glove.js`는 관절 구체나 손톱 없이 손바닥과 다섯 손가락의 윤곽을 한 표면으로 합성합니다. 손바닥은 넓은 음영과 얕은 주름으로 구분하고 팔목은 팔꿈치 방향으로 흐려집니다. GPU 렌더러 없이 Canvas 2D에서 동작합니다. 그립 설명과 자동 시연에서는 이어진 도복 깃을 엄지/손끝 앞에 겹쳐 깃 안쪽으로 들어가는 부분을 표현합니다.

```sh
node --test tests/*.test.mjs
node scripts/browser-live-hands.cjs <Playwright 패키지 경로>
```

실시간 장갑 검사는 합성 관절로 펴기·부분 쥐기·주먹·교차, 검출 순서 반전, 거울 모드, 추적 끊김·복구, 모바일 화면과 카메라 해제를 검증합니다. 실제 웹캠의 손가락 인식 정확도는 조명과 손 가림에 영향을 받으며 이 검사의 측정 범위에 포함되지 않습니다.
